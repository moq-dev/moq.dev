## Potential vs Reality
Every blog post I write about MoQ I rave about the potential.
There's SO MANY COOL THINGS YOU COULD DO WITH MOQ.

But if you actually want to use it *today*, there's so many things you need to implement yourself.
A world-wide CDN is one of those requirements but there are many more *mundane* things.

My goal with [moq.pro](https://moq.pro) is to make it easy to start using MoQ **now**.
Point your clients to a URL and *it just works*.

With this first release we have:
- RTMP / WebRTC / SRT import and export.
- HLS recordings (your bucket or managed).
- Live stats and dashboards (1s granularity).
- Scoped authorization tokens (read/write per prefix).

All of these tools are open source in the [moq](https://github.com/moq-dev/moq) repo.
**You will always be able to self-host.**

**Fun fact**, here's a few of the ways to watch the same content:
- [Web](https://doc.moq.dev/lib/js/@moq/watch.html): `https://moq.watch/?project=demo&name=bbb.hang`
- [CLI](https://doc.moq.dev/bin/cli.html): `moq --client-connect "https://cdn.moq.pro/anon/<broadcast>.hang" export ts | ffplay -`
- [RTMP](https://github.com/moq-dev/moq/tree/main/rs/moq-rtmp): `rtmps://cdn.moq.pro:1935/demo/bbb.hang`
- [SRT](https://github.com/moq-dev/moq/tree/main/rs/moq-srt): `srt://cdn.moq.pro:877?latency=500&streamid=#!::r=demo/bbb.hang,m=request`
- [WebRTC](https://github.com/moq-dev/moq/tree/main/rs/moq-rtc): `https://cdn.moq.pro/whep/demo/bbb.hang`

## The Standard
[moq-transport](https://datatracker.ietf.org/doc/draft-ietf-moq-transport/) will be an RFC soon enough.
There's quite a few companies working on their own CDN offering: [Cloudflare](https://moq.dev/blog/first-cdn/), Akamai, Fastly, AWS, etc.
But progress is *so slow*; it's embarassing.

Hopefully this gives the group a kick in the butt.
Stop arguing about how to *best* encode an integer and actually build something.

All of the [moq.dev](https://moq.dev) clients are fully compatible with the standard, supporting drafts 14-19.
You should be able to switch out the `https://cdn.moq.pro` URL with a different CDN provider (ex. [Cloudflare](https://blog.cloudflare.com/moq-relays/))

The [moq.pro](https://moq.pro) relay doesn't support every feature in the IETF standard.
But to be fair, there are zero implementations that do, owing to the bloated and fragmented nature of the standard.
Hit me up if you want to use a 3rd party MoQ client that isn't compatible and we'll figure out a path forward.
