## Last Time
- The [launch post](/blog/rind) was mostly perf. "Lean into Lean" was one section and hand-wavy ("at least according to Claude so grain of salt").
- It said AES-GCM was faster AND verified. Caveat it here: proven on x86_64 AES-NI (Vale tier + rind's by-8), **not** on VAES CPUs (Zen 3+, Ice Lake+, Alder Lake+), not aarch64, only 12-byte IVs and full tags.
- This post: what "verified" actually means, and everything else we do because proofs aren't enough.

## What Does "Verified" Mean?
- Functional correctness: the API's output equals the RFC/FIPS spec. Glue included, not just the hot loop.
  - The bar is in `benchmarks/verified.toml`: the whole computation, excluding DER parsing and randomness.
- At the first audit ([rind#318](https://github.com/moq-dev/rind/pull/318), Nov 3) under that strict rule, **zero** operations earned a ✓. Good hook.
- NOT proven: memory safety, panic-freedom, constant time (except the asm compares and s2n-bignum's `_SAFE` routines). Say this loudly.

## Proving the Bytes You Ship
- A proof about source is worthless if the compiler/assembler emits something else.
- `admin/prove bytes` ([rind#551](https://github.com/moq-dev/rind/pull/551)) checks the release build's bytes equal the proven object code: 192 s2n-bignum blocks, plus Vale and aws-lc.
- HOL Light proofs extract rind's own emitted bytes.
- Runs in CI (`prove.yml`, nightly + PRs touching proofs/source): `bytes`, `hol-light`, `cosim`, `lean`.

## The Trust Base
- What you still have to believe: Lean's kernel, Charon/Aeneas's translation and `core` models, spec transliterations, imported theorems-as-axioms.
- Hand-written Lean models for Rust Aeneas can't translate (fn pointers, intrinsics, `dyn`). `admin/prove` fails when the quoted source drifts.
- SIMD intrinsic models are tested against the real CPU ([rind#588](https://github.com/moq-dev/rind/pull/588)); rind's x86 model additions checked by cosimulation.
- `Axioms.lean` pins every theorem's axioms with `#guard_msgs` so the trust base can't grow silently. Nice detail.

## Proofs Aren't Enough
- Most of rind is still unproven, and proofs don't cover timing or memory. So every primitive gets five kinds of check, and `admin/testing` fails `just ci` if any primitive is missing one (see `TESTING.md`).

### Test Vectors
- Wycheproof, NIST CAVP, ACVP samples ([rind#555](https://github.com/moq-dev/rind/pull/555)), RFC vectors, CCTV (incl. the 1M-case ML-KEM accumulation), aws-lc + BoringSSL vectors on every CPU tier.

### Differential Fuzzing
- 23 targets fuzzed against aws-lc-rs ([rind#303](https://github.com/moq-dev/rind/pull/303), [rind#535](https://github.com/moq-dev/rind/pull/535)), plus `tests/crosschecks.rs`.
- Hostile-peer bytes through the rustls, dimpl, and str0m adapters ([rind#561](https://github.com/moq-dev/rind/pull/561)).
- Nightly, then the corpus replays on every tier.

### Constant Time
- Taint tracking: ctgrind under valgrind, plus Intel SDE and qemu variants for code valgrind can't run.
- [BINSEC](https://binsec.github.io/) symbolic checks on secret paths no proof covers ([rind#576](https://github.com/moq-dev/rind/pull/576)).
- Static scan of release builds for divisions and floating point on every arch ([rind#586](https://github.com/moq-dev/rind/pull/586)).
- Statistical timing on real hardware: dudect, plus the Marvin toolkit on RSA-OAEP ([rind#483](https://github.com/moq-dev/rind/pull/483)). TODO: a chart from the timing runs?

### Zeroing
- Tests check every byte of every secret type is wiped, on every tier and Windows ([rind#550](https://github.com/moq-dev/rind/pull/550)).

### Memory Safety
- Guard-page tests catch out-of-bounds asm reads/writes; the only bounds check on the fastest tiers ([rind#568](https://github.com/moq-dev/rind/pull/568)).
- Nightly Miri (portable, x86_64, big-endian s390x), ASan (doesn't see asm).
- ABI harness: every asm routine preserves callee-saved registers ([rind#564](https://github.com/moq-dev/rind/pull/564)).
- Safe asm wrappers enforce preconditions in release builds ([rind#583](https://github.com/moq-dev/rind/pull/583)).

### Every CPU
- Intel SDE runs every x86_64 dispatch path, Prescott to Diamond Rapids.
- `RIND_CPU_DISABLE_*` forces the fallback tiers.
- qemu: armv7, s390x, riscv64, PowerPC, armv6, loongarch64. Native arm64, wasm32, iOS sim, Android.

### Testing the Tests
- cargo-mutants nightly, incl. AVX-512 and armv7 ([rind#570](https://github.com/moq-dev/rind/pull/570)); surviving mutants killed in [rind#603](https://github.com/moq-dev/rind/pull/603).

### Process
- An adversarial reviewer's brief (`REVIEW.md`) read from the base branch, so a PR can't soften its own review.
- `AGENTS.md`: Wycheproof + aws-lc-rs differential for every primitive, ctgrind for new secret paths, hostile input errors and never panics, a correctness argument for new arithmetic.

## What's Not Verified (Yet)
- AES-GCM on VAES and aarch64; AES-192.
- SHA-256 block on x86_64 (assumed), SHA-1 blocks everywhere.
- SHA-512/Ed25519 on AVX2/AMD and aarch64-with-SHA512, i.e. most modern hardware.
- ChaCha20-Poly1305 one-pass asm.
- P-256 on x86_64, P-384 keygen, P-521. RSA signing/decrypt/keygen, all RSA on aarch64.
- ML-KEM construction, ML-DSA, SLH-DSA.
- armv7, the portable backend (except Keccak).
- No proofs of memory safety, panic-freedom, or general constant time.
- Some theorems are conditional (CPU-feature checks pass, hand models faithful). ECDSA signing proves a returned signature is correct, not that it terminates.
