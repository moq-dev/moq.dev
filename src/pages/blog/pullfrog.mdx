## The Problem: Review
- MoQ merges a stupid number of PRs now: ~300 merged on moq-dev/moq between Nov 8 and Nov 12.
- Most are agent-written (quests). Nobody can hand-review that volume.
- Our rule: a model other than the latest writer reviews every PR before it's ready.
  - Locally: `quest review` with Codex or Claude, whichever didn't write it last.
  - Online: Pullfrog, which supplies a third model family (DeepSeek). See [moq-dev/moq#8543](https://github.com/moq-dev/moq/pull/8543).

## Pullfrog
- Tagline (theirs): "The BYOK CodeRabbit that runs in your GitHub Actions."
- Agents that triage, plan, build, and review, all inside GitHub. No new UI.
- Runs in **your own** GitHub Actions via `pullfrog/pullfrog`, not on their servers.
- Bring your own key or subscription (Claude, ChatGPT/Codex, Grok, Gemini, DeepSeek, Kimi, OpenRouter, Bedrock, Vertex, ...), or their router at provider cost.
- Free for personal and open source. Org plan is a flat $30/month, no per-seat fees.
- Open source: [github.com/pullfrog/pullfrog](https://github.com/pullfrog/pullfrog).
- Other tricks worth a sentence: fixes CI on its own PRs, resolves merge conflicts, acts on review comments, headless browser for screenshots.

## Security (for the paranoid)
- The workflow only has `contents: read`.
- No provider API keys in the repo: Pullfrog trades a GitHub OIDC token for model access.
- That token can only be minted from the `pullfrog` environment, which only `main` may deploy to, so a pushed branch can't steal model access ([moq-dev/moq#7424](https://github.com/moq-dev/moq/pull/7424)).
- GitHub operations use a short-lived installation token, revoked when the run ends.
- Agent's git/GitHub access goes through an MCP permission layer; it can't push to protected branches.
